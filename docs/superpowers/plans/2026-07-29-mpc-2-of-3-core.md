# MPC 2-of-3 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the generic `mpc-core` runtime with immutable share contracts,
evidence-only key-material inspection, party-addressed concurrent DKG execution,
durable single-use pre-parameter handles, and real 2-of-3 cryptographic proof.

**Architecture:** Product code continues to pass required signer count 2 and
arbitrary generic party IDs to one public `Service`. Core alone converts that
value to the `tss-lib` threshold representation. One service and one shared
pre-parameter pool may execute B and C concurrently under an internal
`(sessionId, localPartyId)` run key. Core owns sealed pre-parameter leases and
exposes only public evidence from encoded ECDSA material.

**Tech Stack:** Go 1.24, `bnb-chain/tss-lib` v1.5.0, secp256k1, file-backed pre-parameter cache, Go race/fuzz/subprocess tests.

## Global Constraints

- Keep the runtime generic; no party purpose, descriptor, backend eligibility,
  AES-GCM artifact, filesystem destination, or terminal-state logic enters core.
- One `Service` and its one shared pool serve both local DKG parties. Do not
  create a service or pool per party, and do not bind a pre-parameter handle to
  B or C before single-use consumption.
- Every DKG service-local lookup that can contain simultaneous B and C state
  uses the internal composite `DKGRunKey{SessionID, LocalPartyID}`. This includes
  temporary shares, active-run registration, export/delete, cancellation,
  result caches, metrics identity, and transport/runtime lookup. The wire
  protocol continues to carry one shared `sessionId`.
- The same session with different local parties is valid concurrently; the same
  session and same local party is a duplicate. Cleanup or failure of one party
  must never delete or corrupt the sibling party's state.
- Public callers pass product threshold/required signer count `2` unchanged.
- Artifact v1 embeds the existing codec v2; decoder compatibility and pinned
  `tss-lib` are retained for the full artifact lifetime.
- Codec-v2 golden vectors and their manifest are owned locally by `mpc-core`.
  Core neither consumes nor copies the signer shared-contract manifest.
- `REQ-081`, `INV-056`, and `DECISION-047` belong entirely to the
  backend-to-co-signer `COSIGNER-HTTP-V1` contract. Core does not vendor,
  verify, generate, or depend on that bundle.
- A pre-parameter handle is sealed, service-bound, opaque, and single-use.
- File-backed acquire returns a handle only after unlink plus directory `fsync`.
- Generic share metadata is immutable and has no status/disable capability.
- `SaveShareInput` is exactly generic persistence context: `SessionID`, `KeyID`,
  `LocalPartyID`, `OpaqueDescriptorFingerprint`, and `CodecBlob`. Product
  purpose, descriptor bytes, and destination routing remain outside core.
- Tests never reconstruct a private key or print shares, chain code, preparams,
  or decrypted key material.
- Committed code and CI use `GOWORK=off`; no committed `replace` directive is
  allowed. A local uncommitted workspace may be used before the module tag.
- Use TDD and one conventional commit per `PLAN-STEP-*`.

### PLAN-STEP-CORE-005: Make file-backed acquisition durably single-use

**Sources:** `REQ-054`, `INV-032`, `RISK-015`

**Depends on:** `PLAN-STEP-CORE-004b`

**Files:**

- Modify: `internal/preparams/pool.go`

- Modify: `internal/preparams/pool_test.go`
- Create: `internal/preparams/cache_subprocess_test.go`
- Create: `internal/preparams/fs_capability_test.go`

**Interfaces:**

- File-backed acquire first removes the selected entry from the in-memory
  acquisition queue, then validates it, unlinks its cache file, syncs the parent
  directory, and only then constructs the handle.
- `ENOENT`, unlink failure, or directory-sync failure returns no handle and
  increments `AcquireFailed`. Any validation or filesystem failure after queue
  removal permanently excludes that entry from the current process pool; it is
  never reinserted or requeued.
- File-backed startup validates a private cache directory, atomic create-only
  publication, file `fsync`, and directory `fsync`. Unsupported durability
  fails the disk-cache lifecycle; an in-memory fallback is allowed only through
  explicit configuration.

- [ ] Add recorder tests for syscall order and helper-process crash barriers
      before unlink, after unlink/before sync, after sync/before return, and after
      return.
- [ ] Add a failing test for every validation/`ENOENT`/unlink/directory-sync
      acquire error proving the selected entry is never requeued in the current
      process and no handle is returned.
- [ ] Add failing capability tests for weak permissions, unsupported
      create-only publication, file-sync failure, directory-sync failure, and
      forbidden silent fallback.
- [ ] Run `GOWORK=off go test ./internal/preparams -run 'Durable|Crash|Acquire' -count=1`;
      expect best-effort removal behavior to fail.
- [ ] Add the narrow filesystem adapter, durable create-only cache publication,
      strict cache loading, unlink+directory-sync acquire, startup capability
      checks, and fail-closed errors. Temporary/malformed entries never enter
      the acquisition queue.
- [ ] Run `GOWORK=off go test -race ./internal/preparams -count=1`; after every
      returned handle, restart must never reload the test entry ID.
- [ ] Assert metrics change only on successful state transitions:
      `acquired`, `consumed`, `discarded_before_start`, `acquire_failed`, and
      `consume_conflict`; a filesystem error before handle creation is only an
      acquire failure.
- [ ] Commit with `feat(preparams): durably consume cached material`.

## Migration, Compatibility, and Recovery

- **Schema/data migration:** N/A — core owns no product database.
- **Module versioning:** removal of public mutable share interfaces is a
  breaking change for this pre-1.0 module, so the release is the minor bump
  `v0.3.0`, not a `v0.2.x` patch.
- **API ordering:** land immutable share interfaces, composite-key execution,
  and handle APIs before co-signer consumes them; signer party A may keep
  `RunDKGSession`.
- **Codec compatibility:** v2 decoding remains mandatory; no artifact v1 codec
  bump is allowed by this PLAN. The codec corpus remains local to core.
- **Rollback:** callers cannot roll back after adopting the removed mutable
  interface without a coordinated source rollback. No persisted B/C artifact
  is migrated by core.
- **Cache recovery:** entries returned as handles are never recoverable/reused;
  pre-sync failures return no handle; malformed/temp entries never enter the
  acquisition queue.
- **Partial failure:** any error after consume burns the material; capacity loss
  is accepted and refill restores inventory later. Party-specific DKG cleanup
  affects only its composite run key.
- **Dependency cut:** consumers merge core-dependent changes only after
  `MPC-CORE-V0.3.0`; local `go.work` or uncommitted `replace` development state
  is never committed or used by CI.
